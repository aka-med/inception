Technical Projects

RedDrop (ft_transcendence) — ongoing

Java 21 • Spring Boot • Spring Security • JWT • PostgreSQL • Flyway • React • TypeScript • Docker • Nginx
  • Building a blood-donation platform for Morocco in a team of 5, where donors find centers, check their eligibility and book appointments, and staff validate donations through role-based dashboards.
  • Own the Spring Security filter chain: a custom OncePerRequestFilter reads the JWT from an HttpOnly cookie on every request and checks its signature and scope. It also checks the user's current role and token version in the database, so logout, a password change or a role change ends the session instantly on every device.
  • Configured stateless sessions, an ordered deny-by-default set of URL rules, method-level @PreAuthorize checks, a CORS allow-list with credentials, and JSON 401/403 responses in the API's single error format instead of HTML redirects.

Inception — Docker Web Infrastructure

Docker • Compose • Nginx • WordPress • PHP-FPM • MariaDB • Redis • Debian
  • Designed and built a 7-service web stack: Nginx, WordPress with PHP-FPM, MariaDB, Redis, Adminer, an FTP server and cAdvisor. Every image is written from scratch on Debian Bookworm, with no prebuilt service images, and the whole stack is orchestrated with Docker Compose and run through a Makefile.
  • Made Nginx the only HTTPS entry point to the web stack: TLS 1.2/1.3 with a certificate generated at build time, forwarding PHP requests over FastCGI to WordPress and Adminer on an isolated internal network that the containers reach by service name.
  • Kept all credentials out of images and environment variables with Docker secrets, read from files at startup. Data persists on host-backed volumes, and each service runs in the foreground as the container's main process.

ft_irc — IRC Server

C++98 • POSIX Sockets • poll() • Makefile
  • Built an IRC server from scratch in a team of 3. It works with standard clients such as irssi and covers registration, channels, operator modes, private messaging and a calculator bot.
  • Owned the networking core: set up the listening TCP socket (SO_REUSEADDR, non-blocking mode, bind/listen) and accepted new clients as non-blocking connections registered in a single poll() event loop.
  • Drove all client I/O through one loop with buffered reads and writes (POLLIN/POLLOUT), and cleaned up disconnects and socket errors (POLLHUP/POLLERR). Handled SIGINT/SIGQUIT for a graceful shutdown and ignored SIGPIPE so a dropped client can't crash the server.
